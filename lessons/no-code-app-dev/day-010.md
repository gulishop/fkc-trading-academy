# Day 10 — **No-Code ki Limitations: Kab Use Karna Chahiye aur Kab Nahi?**

**Concept:**
No-code tools powerful hain, lekin har samay sabkuch solve nahi karte. Inki limitations samajhna zaroori hai taake aap realistic expectations rakhein. Common issues: customization limits, performance bottlenecks, vendor lock-in, aur complex logic handle na kar paana. Jaise FlutterFlow se advanced animations ya Webflow se dynamic database queries mushkil hoti hain.

**Example:**
Ek student ne Glide se ek e-commerce app banaya. Usne payment integration ki, lekin custom discount engine ya real-time inventory sync nahi kar paaya. Glide ke built-in features se yeh possible nahi tha, isliye usko custom code (low-code) ya alternative solution (jaise Airtable + Make.com) ki zaroorat padi.

**Practice:**
Apne current project mein **ek limitation** identify karo jo aapko lagta hai aapka no-code tool handle nahi kar paa raha. Likh do: *"Meri [tool name] se yeh problem hai: [problem ka naam]"*.

**Mini Project:**
Ek **"No-Code vs Low-Code"** comparison chart banayein. Do columns mein:
1. **No-Code Limitations** (e.g., "Custom animations impossible")
2. **Low-Code Workaround** (e.g., "Framer + custom JS snippet")
Use 3-4 tools (Webflow, FlutterFlow, Glide, Bubble) ke liye fill karo.

**Answer Key:**
customization limits, vendor lock-in, performance issues, complex logic
